# Можно

Рабочее описание учебной версии, 18 ноября 2026. Основа проекта это курсовой цифровой банк с помощницей Кэи. Будущий состав экранов и вторая роль пока не согласованы.

## 1. Пользователь

Клиент «Можно», который распределяет деньги по назначениям и хочет понимать, может ли позволить себе покупку.

## 2. Зачем

Помочь увидеть свои кармашки с деньгами и получить понятное объяснение последствий покупки, сохраняя решение за человеком.

## 3. Ключевой сценарий

Открыть «Можно» → спросить Кэи «Можно мне…?» → увидеть ответ с объяснением → решить, покупать сейчас или отложить. В учебной версии платежи не выполняются. Будущая ИИ-функция объясняет ответ на основе доступных данных, сейчас она ещё не реализована.

Первый реализованный шаг к КТ-1 это просмотр четырёх кармашков на экране «Счета», данные заранее записаны в файле. База и вход для этого шага не нужны.

## 4. Экраны и роли

Предложены для обсуждения пять экранов: вход, главная Кэи, счета, форма кармашка, диалог «Можно мне…?». Пока реализован только блок кармашков на «Счетах»; /design-system служит технической проверке оформления.

Основная роль это клиент. Требование второй роли уточняем у преподавателя, вопрос отправлен 18 ноября, ответ пока не получен. Администратор пока только возможный вариант. Уровни доверия к Кэи не считаем пользовательскими ролями. Ответ может изменить состав экранов.

## 5. Основная сущность

Кармашек. Сейчас учебная запись содержит id, название, сумму в рублях и подпись. Далее для той же сущности планируются создание, просмотр, изменение и удаление; они ещё не реализованы целиком. Цели, даты и правила закрытия непустого кармашка нужно согласовать отдельно. Кармашек в концепции банка остаётся счётом.

Не в этом курсе: реальные платежи и переводы, подключение банков, инвестиции и перенос всех экранов курсового. Используем учебные данные; подключение Supabase и API модели относится к следующим этапам.
