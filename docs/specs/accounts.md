# КТ-1 «Можно» — первый блок экрана «Счета»

17 ноября 2026. Влада выбрала «Счета» с кармашками. Выбор экрана подтверждён; план блока из четырёх кармашков принят сообщением «газ кармашки». Реализация начата после принятия. Вопрос преподавателю о второй роли не мешает первой версии на учебных данных.

## Что получится

Вместо заготовки преподавателя по локальному адресу появится первая часть «Можно»: заголовок «Счета», раздел «Кармашки · 4», четыре карточки по существующему макету. Первый шаг охватывает именно блок кармашков, не весь экран счетов со всеми возможностями. Переводы, оплата, списания, открытие нового счёта и нижняя навигация в первый шаг не включены; не рисуем кнопки, обещающие пока недоступные действия. Сокращение до четырёх кармашков принято Владой до кода.

Источник: https://www.figma.com/design/cpfQkvSnkrRnbJ2SOYXLoE?node-id=941-5801. Макет просмотрен 17.11. Общая сумма 63190 и реальная модель её расчёта не входят в этот блок. На макете указано 7 кармашков с пролистыванием, здесь предложение сделать 4 видимые карточки и честный счётчик 4 без карусели. Визуальное оформление берём из существующего дизайна «Можно»; не придумываем новый стиль.

## Задача в пять строк

1. Что: показать список учебных кармашков на странице «Счета».
2. Для кого: клиент «Можно», которому нужно посмотреть распределение денег.
3. Сценарий: открыть страницу → увидеть названия и суммы четырёх кармашков.
4. Проверка: в данных четыре объекта → на странице четыре карточки; названия и суммы совпадают с источником данных, подпись сообщает 4.
5. Не делать: не подключать базу, ИИ или реальные деньги; не ставить новые пакеты, не придумывать вторую роль, не добавлять формы и оплаты.

## Учебные данные из просмотренного макета

Свободно: 18000 ₽; На себя: 2000 ₽; Аренда: 25000 ₽; Отпуск: 6000 ₽. Это демонстрационные значения из дизайна, не финансы Влады. Не рассчитывать доступную дневную сумму из этих четырёх карточек без модели денег. Дополнительные пояснения карточек брать только из проверенного макета; даты ноября не выдавать за текущий прогноз.

## Предложенный план файлов

Все пути ниже внутри student-app/.

- `lib/demo-pockets.ts`: четыре учебные записи, у каждой постоянный id, название и сумма в рублях. Изменение здесь должно менять содержимое карточки.
- `components/pocket-card.tsx`: одна карточка, получающая название и сумму. Один шаблон используется четыре раза, оформление совпадает.
- `app/page.tsx`: убрать стартовый контент, собрать заголовок и список из учебных данных. Отдельный маршрут на первом шаге не нужен.
- `app/globals.css`: перенести необходимые существующие визуальные настройки «Можно» в именованные токены; не прописывать произвольные цвета и размеры в каждой карточке. Проверить Figma и действующие инструкции Next перед реализацией.
- `app/layout.tsx`: обновить название страницы на «Можно» и подключить нужный шрифт, если это не потребует нового пакета. Способ подключения шрифта определить по доступным исходным ассетам и возможностям проекта.
- `tests/e2e/start.spec.ts`: обновить прежнее ожидание заголовка, проверить четыре карточки с нужными названиями/суммами. Прежний тест не удалять ради зелёного результата.
- `docs/specs/accounts.md`: перенести принятую задачу/план и затем фактический результат проверки в репозиторий.
- `DECISIONS.md`: до коммита добавить реальное решение, альтернативу главной, авторство и причину. Не записывать одобрение до ответа Влады.

Документы PRODUCT, CLAUDE, DESIGN и README тоже обязательны к КТ-1. Их заполнение идёт отдельным понятным шагом; роль/окончательный объём продукта пока открыты, не объявлять их утверждёнными. До работы агента заполнить проверяемые правила CLAUDE/AGENTS отдельным предложенным планом либо явно включить их в согласование, сохранив служебный блок Next.

## Как проверяем

- Вид страницы на узком экране и в широком окне, читаемость сумм, отсутствие горизонтального обрезания.
- Сверка имён и сумм с учебным набором, число карточек и подпись.
- typecheck, unit, сборка, существующий e2e после обновления ожиданий. Если для e2e нужен браузер, установка отдельным подготовительным действием, не новым пакетом проекта.
- Просмотр git status, diff, новых файлов и diff --cached перед сохранением.
- Показать Владе страницу и объяснить цепочку «данные → карточка → экран». Её проверка и понимание ещё не подтверждены.

## Возврат после ручного упражнения

17 ноября Влада вернула amountRubles у «Отпуска» с 6500 на 6000. Файл и 6 000 ₽ в браузере проверены Codex. Упражнение выполнено пользователем; ручная правка и возврат не являются git revert. Исходные данные восстановлены, проверенные ранее ожидания тестов снова соответствуют им.

Рабочую фичу с необходимой основой ДС, спецификациями и решениями сохраняем одним отдельным коммитом. Новая возможность — просмотр кармашков; перенос ДС служит её оформлением. Учебная поломка отдельным коммитом и git revert будут следующим отдельным упражнением; здесь они не имитируются.
